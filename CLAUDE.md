# hugr-platform - Development Guidelines

The hugr platform's orchestrator: a Kubernetes operator. It keeps the node groups (`HugrNodeGroup`, edited with
standard tooling), answers a node's entry with its bootstrap document, records the heartbeat in Leases, and is a client
of the nodes with its own identity, reading only. The policy and the cluster profile stay SQL's, in the policy
catalog. The front
(the balancer the clients reach) and the web console come from the same repository. Read `README.md` first, then the
specs in `specs/`.

## Technology

- **Go** (the same stack as kista, hugr-lab/duckdb-extension-repository), one module.
- **A Kubernetes operator** on controller-runtime: the custom resources `HugrPlatform` and `HugrNodeGroup` hold the
  desired state, Leases and the resources' status hold the fleet's. **No database of its own.**
- **Shared logic in packages with no Kubernetes dependency** (`pkg/`: the node protocol, the plan's judgement), so a
  bare-metal service can import them when one is needed - not before.
- **Authentication**:
  - A node is a pod of a group: its projected ServiceAccount token, checked by TokenReview.
  - The operator itself is a workload identity federated into the organisation's IdP, a client of the nodes like
    any principal (provided for in `HugrPlatform`; the client itself comes with the console, spec 003).
  - People sign in through the same IdP.

## Rules the owner set

- **One lightweight spec per feature**, `specs/NNN-slug/spec.md` from `specs/TEMPLATE.md`. The owner accepts a spec
  before its code is written. One branch per spec (`NNN-slug`), and push only when asked.
- **Every change lands with tests**, and three adversarial self-review passes come before a PR.
- **PR flow**: CI green, then squash-merge, then check the main runs.
- **Never a credential at rest**: nothing in the resources, the documents or the logs.
  - A bootstrap document holds pointers only, and a secret is named, never carried.
  - A token is never logged; a refusal names the account and the pod.
- **The control plane decides nothing for a node.** It serves what the operator configured and records what nodes
  report. Profile, policy and secrets have their own homes (the policy catalog, tresor-server).
- **Products stay products.** kista and tresor-server are used through their protocols; their sessions get only
  product gaps the platform needs, never our deployment configuration.
- **Scale by statelessness**: any replica answers any request, state lives in Kubernetes, and "lost" is an expired
  Lease. Reconciling is the leader's.

## Layout

```text
api/v1alpha1/        HugrPlatform, HugrNodeGroup (zz_generated.deepcopy.go by controller-gen)
pkg/nodeproto/       the node protocol: document v2, the heartbeat, the Lease's summary - no Kubernetes dependency
pkg/plan/            the plan's judgement of groups (the webhook's and the reconcile's) - no Kubernetes dependency
internal/build/      a group's objects and its bootstrap document (pure; golden files in testdata/)
internal/controller/ the group reconciler: the plan again, the objects by server-side apply, status from Leases
internal/webhook/    the validating webhook of HugrNodeGroup
internal/nodeapi/    GET /v1/bootstrap, POST /v1/heartbeat: TokenReview of the pod's bound token, the pod's Lease
cmd/operator/        the binary: manager, leader election, webhook, the node API on every replica
config/              CRDs, RBAC, webhook (generated by `make manifests`) + manager, cert-manager, kustomize default;
                     policy/ the optional admission policies (a group's pods come only from its own chain)
test/envtest/        envtest (build tag envtest): a real API server and etcd, no kubelet
```

## Commands

A `go.work` above the checkout is not this module's: every target runs with `GOWORK=off`.

```sh
make generate manifests   # deepcopy, CRDs, RBAC, the webhook's registration (CI checks they are current)
make lint                 # gofmt, go vet, staticcheck
make test                 # the unit tests and envtest (setup-envtest fetches the pinned API server)
go test ./internal/build -update   # rewrite the golden files after a deliberate change
make image                # ghcr.io/hugr-lab/hugr-platform:dev (distroless)
```
